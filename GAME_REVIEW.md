# Northstar Guidance (Event Sim) — Review

Read-only pass over the current build. No code was changed for this review. Opinions below are mine, based on reading the source (`engine.ts`, `missions.ts`, `house.ts`, `profiles.ts`, `Screens.tsx`, `GameView.tsx`) and playing through the demo family in a real browser.

## Look / visual

1. **Two art styles collide.** The title screen is a painterly, photoreal illustration (dusk house, warm lighting). The actual gameplay is flat vector/cartoon sprites (Maya, Leo, furniture icons) on a plain tile-grid floor. The jump from one to the other when you click "Play a demo family" is jarring — it reads as two different products stitched together. Either the title art should be restyled closer to the in-game palette, or the in-game floors/rooms need some of the title screen's warmth (soft lighting, texture) so the transition doesn't feel like a downgrade.
2. **Rooms are bare.** Each room is a flat gray/tan rectangle with 1-3 floating icon-props (a couch, a bed, a fridge) and a label in the corner. There's no wall detail, no windows, no decoration — it reads more like a wireframe than a home. Even simple per-room floor textures (already loaded! `floor-wood.jpg`, `floor-carpet.jpg`, etc. exist in `public/game` but I didn't see much visual variety pop in play) and baseboards/wall shading would make the house feel lived-in rather than blocked out.
3. **The compass-rose / parchment styling is nice but only shows up in the dialogue and setup screens.** It's a distinctive visual identity (matches the "Northstar" brand) that doesn't extend into the actual play view — the HUD chrome (buttons, steps card) is plain, generic rounded rectangles. Carrying the parchment/compass motif into the in-game HUD would tie the whole experience together.
4. **Family member "pawns" (Priya, David, Leo when not playing them) are static single-frame images with no idle animation** — they just stand there like cardboard cutouts while the player animates in a 4-direction walk cycle. Even a subtle idle bob/blink would sell them as characters rather than props.
5. **No feedback juice on pickup/interact.** Collecting a kit item or flipping the breaker just marks a step done in the corner list — no sparkle, sound sting, or brief highlight on the object itself. For the target audience (kids), a small celebratory flourish per objective would matter a lot.

## Gameplay / design

1. **All four drills are the same shape: walk to N marked points, press Use, done.** There's no real time pressure, no wrong choice, no branching consequence — "power-out," "pack-kit," "neighbor," and "rally" are functionally identical checklists with different labels. For a training game about calm-but-real preparedness, that's probably intentional (low-stakes practice), but it also means there's no replay incentive once a kid has done it once. Worth considering: a light optional timer/best-time, or slight variation in item/NPC placement each run, so replaying isn't just retracing the same path.
2. **Star rating feels arbitrary.** `stars = done === total ? 3 : done > total/2 ? 2 : 1` — since every step is mandatory to progress (you can't finish without doing them), in practice everyone gets 3 stars every time. The scoring exists but doesn't currently differentiate anything.
3. **Learning-choice dialogues (flashlight okay/needs batteries, water yes/not sure) are the most interesting mechanic in the game** — actual branching feedback tied to real prep knowledge — but there are only a couple of them, tucked away as side content. This is the strongest teaching moment in the build and feels underused compared to the walk-and-collect loop.
4. **No difficulty/age adaptation.** Confirmed target audience is ages 6-12, but a 6-year-old (Leo) and a 9-year-old (Maya) currently get the exact same drill complexity and hint text — the game doesn't flex across that range at all. Given the profiles already track age/role, scaling hint verbosity, step count, or reading level by the played character's age seems like the highest-value fix in this list: a 6-year-old and a 12-year-old have very different reading ability and attention span, and right now both get identical text-heavy dialogue cards.
5. **Idle nudge exists but is generic** (`idle > 14` triggers a hint toward the next undone step) — good pattern, but it's the same nudge regardless of which drill or how long they've been stuck; a kid stuck for 60s probably needs a stronger nudge than one stuck for 15s.
6. **Neighbor and rally drills depend on data that's easy to leave empty** (`profile.neighbors[0]`, `plan.meetingPlace`) — if a real customer record doesn't fill these in, those drills probably degrade to something confusing ("Find your neighbor" with no one placed, or a rally point with a placeholder name). Worth double-checking the empty-data path.
7. **Mobile controls are functional but minimal** — a joystick + one "Use" button. Given the fixes already made (steps placard now visible on mobile), it might be worth a pass on hit-target sizing for the joystick/Use button on small phones specifically, since that's likely the primary device for this audience in practice.

## Smaller things worth a glance later

- Pre-existing (unrelated to anything touched this session) TypeScript errors in `house.ts` (`"desert"` compared against a narrowed type that excludes it) — not urgent, but should be cleaned up since it means `desert` homes may silently skip a branch of room-generation logic.
- `maya-sheet.png` / `leo-sheet.png` in `public/game` are dead files — not referenced anywhere in code (confirmed via grep). Same broken art as the old `maya.png`/`leo.png` were. Safe to delete whenever, or worth re-checking if there was a planned walk-cycle-per-character feature that never got wired up.
- The dialogue card's `?v=restore2` cache-busting query param on the maya/leo asset URLs is a sign of a previous manual fix attempt that didn't actually change file content — now that the files are genuinely fixed, that param is no longer needed (harmless to leave, but worth knowing it's vestigial).
